# HTML 与 AI 接入安全修复

本次针对审查中优先级最高的四项问题：浏览器模型 Key、Markdown / AI 预览、核心 HTML 输入过滤、附件名称渲染。

## 接入行为变化

- 不再支持在前端配置共享模型长期 Key，也不再默认直连供应商。AI 使用明确配置的同源代理及当前会话的 CSRF token；宿主后端负责认证、供应商密钥、额度与超时。未配置代理时明确拒绝请求，不会伪造生成成功。
- HTML 净化器随编辑器构建提供。不能使用事件属性、活动脚本或伪造内部元数据绕过净化；净化器缺失或浏览器不受支持时只能显示纯文本，不放行原始 HTML。
- iframe 不再拥有脚本和同源权限。依赖这类权限的旧嵌入内容需要按应用的信任边界重新设计，不能通过关闭过滤恢复执行。
- 附件名称按纯文本展示，插入链接时分别编码文本与属性，正常中文、引号和 emoji 名称应保留。

相关实现自然触及的 AI 请求路径也修正了提示模板污染及流式数据的结束处理。这不是对审查全部问题的修复声明；草稿账号隔离、存储异常、全部旧依赖升级及其他审查条目仍需单独处理。

## 部署边界

1. 从当前源码重新构建并部署 `dist` 或 `dist-min`，不要只复制某个单独修改的脚本。
2. 删除前端真实模型 Key；若曾发布过，应由密钥所有者撤销并轮换。客户端代码无法抹掉用户已经下载的旧配置。
3. 接入宿主受认证的同源 AI 代理，验证服务端 CSRF、额度限制及日志脱敏。本仓库没有你的生产代理，也没有打通真实模型。
4. 仓库中 Vue / React 示例自带的历史静态副本不等于当前构建产物。使用这些框架时，应按 README 从当前构建更新集成目录；未更新的旧副本不包含本次安全修复。
5. 应用服务端仍需对上传、持久化和最终展示做自身安全校验；客户端净化不是生产安全验收的替代品。
6. iframe 沙箱隔离执行权限，并不阻止其初始导航请求；图片等外部资源也可能发起网络请求。宿主不能用无 CSRF 保护的 GET 路由执行状态变更。对资源来源有额外要求的业务还需配置自己的来源策略，不能把沙箱当成网络隔离。

测试与实际验证结果见 [验证说明](security-validation.md)，接入合同见 [AI 代理文档](ai-proxy.md) 和 [HTML 安全边界](html-security.md)。
